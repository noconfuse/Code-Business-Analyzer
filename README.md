# Code Business Analyzer

## 你的代码是资产，还是负债？

每个开发者都经历过这个时刻：你写了一个项目，投入了数百小时，技术栈很新，代码很干净，README 写得很认真。然后呢？

然后它躺在 GitHub 的某个角落里，Star 停在个位数，没有人用，也没有人 fork。六个月后你自己都快忘了它存在。

**代码本身不产生价值。** 一段写得再漂亮的代码，如果没有市场需要它、没有竞争壁垒保护它、没有商业模式支撑它，它就不是资产——它是负债。占用你的注意力，消耗你的维护时间，让你误以为自己在创造价值，实际上只是在写一个更精致的 TODO 列表。

反过来，一些代码质量平平、甚至有点脏的项目，因为踩中了真实的痛点、站在了趋势的风口上，反而成了真正的资产——它们吸引社区、带来收入、甚至改变一个细分领域的格局。

**问题是：你怎么知道你的项目是哪一种？**

---

## 这是什么

Code Business Analyzer 是一个 Skill，它对代码项目进行全方位商业分析，生成一份专业的 HTML 报告。

它不告诉你"代码写得好不好"——那是 linter 的活。

它回答一个真正重要的问题：

> **这个项目值不值得继续投入时间迭代？**

为了回答这个问题，它从六个维度拆解你的项目：

| 维度 | 它在问什么 |
|------|-----------|
| 代码质量 | 你的代码地基是否牢固到支撑后续迭代？ |
| 市场与赛道 | 你选的赛道是顺风还是逆风？市场够大吗？ |
| 竞品与护城河 | 别人做一样的东西了吗？你凭什么挡住他们？ |
| 商业价值 | 你的项目通过什么机制赚钱？这个机制成立吗？ |
| 投资决策 | 综合以上，GO、谨慎、还是 NO-GO？ |
| 未来方向 | 如果继续做，下一步该干什么？ |

---

## 它不是"AI 写一份漂亮话"

市面上很多"AI 分析报告"的共同问题是：看起来什么都说了，实际上什么都没说。"前景广阔""值得期待""有一定优势"——这些话的信息量为零。

这个 Skill 用三层机制对抗空话：

### 1. 方法论锚定

每个分析维度绑死一个经过验证的商业方法论，不允许自由心证：

| 分析维度 | 锚定方法论 |
|----------|-----------|
| 代码质量 | ISO/IEC 25010 |
| 护城河 | Porter 五力模型 |
| 同质化 | Blue Ocean Strategy (W SR Framework) |
| 市场规模 | TAM / SAM / SOM 三层漏斗 |
| 用户价值 | Jobs-to-be-Done |
| 商业模式 | Business Model Canvas |
| 采用阶段 | Crossing the Chasm |
| 创新类型 | Christensen 颠覆性创新理论 |
| PMF 验证 | Lean Startup |
| 投资评级 | 调整后 BCG Matrix 逻辑 |

### 2. Kill Criteria（一票否决）

命中任一条硬规则，投资判定自动降档，Agent 无权覆盖：

- 同质化指数 ≥ 8 且赛道竞品 ≥ 5 个 → 最高"谨慎"
- 核心依赖已归档或 EOL → 降一档
- 项目 6 个月无提交 → 自动 NO-GO

规则是阶段感知的——萌芽期项目不会因为"没有商业化验证"或"没有 git 历史"而被误杀，改用投资人否决信号做正向加分评估。

### 3. 魔鬼代言人

在给出最终判定之前，Agent 必须先写 3 条"为什么这个项目应该被毙掉"的论点，再写 3 条"为什么值得继续"。最终判定必须回应反方论点——如果反方论点无法反驳，判定不得高于"谨慎"。

## 五类价值创造机制

不同项目创造商业价值的底层机制不同，用同一套标准评估是不公平的。Skill 会在分析时先识别项目的主价值类型，再套用对应的评估框架：

| 类型 | 核心判断 | 典型代表 |
|------|---------|---------|
| **先进工具** | 效率提升 ≥ 10 倍？用户有切换动力？ | Stripe、Cursor |
| **普惠化** | 新用户群体规模？替代品是"什么都不做"？ | Canva、Notion |
| **信息差消除** | 冷启动怎么过？双边正反馈能否自转？ | 淘宝、大众点评 |
| **细分痛点** | 有人正在用劣质替代品绕过？ | Calendly、1Password |
| **趋势载体** | 趋势不可逆？项目是趋势本身还是过渡形态？ | OpenClaw、Tesla |

一个 Stripe 式的先进工具和一个淘宝式的双边平台，评估标准完全不同。Skill 会按主类型调整投资评级权重。

## 数据可信度

报告中的每个外部数据都标注来源和可信度等级：

- **A 级**：权威引用（Gartner / IDC / 年报 / GitHub 公开数据 / 政府统计）
- **B 级**：行业估计（科技媒体 / 行业白皮书）
- **C 级**：模型推断（AI 推理，无法验证）

任何无法溯源的数据必须标注 C 级。附录提供完整溯源表，逐条对应报告中的 [源N] 引用。

宁可信标注"N/A"，也不编造数据。

## 报告长什么样

报告输出为单个 HTML 文件，视觉风格由 `assets/report_template.html` 的 CSS 决定。当前为黑白硬朗风格——纯黑/白/灰，无渐变、无圆角、无阴影、无 emoji。想换风格？改模板就行，不需要动 Skill 逻辑。

8 章 + 附录：

```
01. 执行摘要         — 一句话定位 + 5 条核心发现
02. 项目概览         — 基本信息表 + 五维评分卡
03. 代码质量         — 六维雷达图 + 竞品代码对标 + Top 5 风险
04. 市场与赛道       — TAM/SAM/SOM + 趋势风向 + 赛道阶段
05. 竞品与护城河     — 量化对比 + 同质化指数 + 六维护城河 + SWOT
06. 商业价值         — 价值类型分析 + 商业模式 + 投资评级
07. 投资决策         — 判定卡 + 决策矩阵 + 魔鬼代言人 + 行动建议
08. 未来方向         — 路线图 + PMF 验证路径 + 风险应对
附录. 数据溯源       — 可信度分级 + 完整溯源表
```

判定结果用三个几何符号表示：

- **■ GO** — 继续重点迭代
- **□ 谨慎** — 有条件推进，附带转绿条件
- **▲ NO-GO** — 建议暂停

## 设计理念

1. **代码是手段，不是目的。** 报告的价值不在描述代码有多好，而在判断代码背后的商业判断是否成立。
2. **客观到严苛。** 宁可误杀一个好项目，也不放过一个坏项目。魔鬼代言人机制确保每个 GO 判定都经过了反方挑战。
3. **方法论 > 直觉。** 每个结论都锚定一个经过验证的框架，减少主观偏差。Agent 不是在"给意见"，而是在"执行框架"。
4. **量化 > 文字。** 能用数字说清楚的不用文字。同质化指数 7.2 比说"差异化不足"有用得多。
5. **数据可溯源。** 每个外部数字都标注来源和可信度。读者可以自行验证，也可以自行降权。
